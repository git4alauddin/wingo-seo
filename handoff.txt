## 5. INTERACTIVE EDUCATIONAL TOOLS

### A. WinGo Mechanics Simulator

Create a self-contained browser simulation demonstrating:

- Numbers 0 through 9.
- Big and Small classifications.
- Red, Green, and Violet classifications.
- Round timers.
- Randomly generated outcomes.
- Recent simulated outcome history.
- Visual statistics.
- Repeatable educational experiments.

Use explicitly documented classification rules from the selected example ruleset. Account for special numbers and overlapping color classifications rather than assuming each number has exactly one color.

All outcomes must be generated locally using a clearly documented simulation model.

The simulation must not connect to real games or claim to forecast external results.

### B. Probability Calculator

Allow users to explore mathematical probabilities.

Example experiments:

- Probability of selecting a particular number.
- Probability of Big versus Small under a uniform 0–9 model.
- Probability of specific outcome sequences.
- Differences between theoretical and observed frequencies.
- Effects of sample size.
- Distribution of results over repeated trials.

The calculator must explain its assumptions.

For a uniform ten-number model:

- Each number has a theoretical probability of 10%.
- Big and Small each have a theoretical probability of 50%, assuming five numbers in each category.

These probabilities describe the specified mathematical model, not necessarily any external operator's actual outcome-generation process.

### C. Pattern and Randomness Demonstration

Build an interactive tool that:

- Generates synthetic outcome sequences.
- Displays streaks and frequency distributions.
- Demonstrates sampling variation.
- Explains the gambler's fallacy.
- Compares small versus large sample sizes.
- Shows why historical streaks do not establish future predictive certainty.

If a prediction-themed demonstration is retained, label it clearly as a simulated guess and disclose that it has no verified predictive advantage.

## 8. TECHNICAL SEO REQUIREMENTS

Implement the following:

**Crawling and indexing**

- Clean, descriptive URLs.
- Server-rendered or prerendered indexable content.
- Proper HTTP status codes.
- XML sitemap.
- Valid robots.txt.
- Self-referencing canonical URLs where appropriate.
- Internal linking between related pages.
- No accidental `noindex` directives on production educational pages.
- Appropriate handling of nonexistent URLs with a real 404 response.
- No indexing of staging environments or duplicate preview deployments.

**On-page SEO**

- Unique page titles.
- Useful meta descriptions.
- Exactly one meaningful primary H1 per page.
- Semantic HTML.
- Descriptive link text.
- Image alternative text.
- Open Graph metadata.
- Logical breadcrumb navigation.

**Structured data**

- Organization or WebSite schema where appropriate.
- BreadcrumbList for qualifying pages.
- Article schema for actual articles where valid.

Structured data must match the visible page content. Do not add unsupported review ratings or misleading rich-result markup.

**Performance**

Target good Core Web Vitals:

- LCP: 2.5 seconds or less.
- INP: 200 milliseconds or less.
- CLS: 0.1 or less.

Evaluate the 75th percentile of real-user measurements when sufficient data becomes available.

Optimize images, fonts, JavaScript, CSS, and caching appropriately.

Use Lighthouse and PageSpeed Insights for initial diagnostics, while recognizing that laboratory test scores are not the same as real-user Core Web Vitals.
